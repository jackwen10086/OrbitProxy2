# Orbit Proxy 产品需求文档

## 1. 产品概述

Orbit Proxy 是一个面向 Windows 的 Electron 网络代理与开发环境管理客户端，核心能力包括：

1. 导入和管理 VLESS、VMESS、Shadowsocks 节点。
2. 为每个远程节点创建独立的本地 SOCKS5 端口。
3. 提供类似 Clash、v2rayN 的系统代理、TUN、DNS 和路由分流能力。
4. 将指定 Windows 程序绑定到指定 SOCKS5 端口。
5. 管理多个 Claude Code 账号、项目、浏览器身份和独立配置目录。
6. 为所有 Claude Code 实例提供全局固定出口 IP。
7. 通过卡密、设备绑定和到期时间控制软件授权。

当前仓库已经实现产品前端原型，真实代理、进程、文件系统和授权逻辑需要通过 Electron 主进程实现。

---

## 2. 用户与使用场景

### 2.1 普通代理用户

- 批量导入订阅或分享链接。
- 测试节点可用性和延迟。
- 切换系统代理模式。
- 为浏览器、开发工具或其他程序获得独立 SOCKS5 地址。

### 2.2 多账号 Claude Code 用户

- 一台电脑只安装一份 Claude Code。
- 每个账号使用独立 `CLAUDE_CONFIG_DIR`。
- 每个项目默认绑定一个账号、浏览器身份和终端。
- 点击“一键启动”即可进入项目目录并使用正确账号运行 Claude Code。
- 多账号并行开发时使用 Git Worktree，避免覆盖同一份文件。

### 2.3 软件运营方

- 通过卡密控制授权。
- 控制授权到期时间和设备数量。
- 撤销泄漏或滥用的授权。
- 客户端不能通过修改本地时间或配置文件绕过授权。

## 3. 节点管理

### 3.1 支持协议

- VLESS
- VMESS
- Shadowsocks

架构应允许后续添加 Trojan、Hysteria2、TUIC 等协议。

### 3.2 导入方式

- 粘贴单条分享链接。
- 使用空格、换行或制表符分隔后批量导入。
- 从二维码图片识别分享链接。
- 从剪贴板读取。
- 从订阅地址更新节点。

导入时应：

1. 校验协议和基本字段。
2. 去除重复节点。
3. 不在日志中输出完整凭据。
4. 返回每条链接的成功或失败原因。
5. 默认允许为导入节点一键创建 SOCKS5 端口。

### 3.3 节点操作

- 测试 TCP 连通性。
- 测试真实代理出口。
- 测量延迟。
- 设为当前系统代理节点。
- 生成本地 SOCKS5。
- 导出分享链接。
- 生成可扫描二维码。
- 删除节点。

删除节点时必须同步删除：

- 该节点关联的 SOCKS5 端口。
- 使用该端口的应用代理规则，或将规则标记为失效并要求用户确认。

如果节点被 Claude Code 固定出口使用，不允许直接删除，必须先解除绑定。

## 4. 本地 SOCKS5

每个 SOCKS5 配置包含：

- ID
- 监听地址，默认 `127.0.0.1`
- 监听端口
- 远程节点 ID
- 运行状态
- 创建时间
- 最后错误

功能：

- 自动选择未占用端口。
- 自定义端口。
- 启动、停止、重启和删除。
- 更换远程节点。
- 复制 `socks5://127.0.0.1:端口`。
- 导出 SOCKS5 二维码。
- 默认不监听局域网，开启 LAN 监听时必须显示安全警告。

## 5. 系统代理与路由

### 5.1 路由模式

#### 绕过大陆

- `geoip:private` 直连。
- `geoip:cn` 直连。
- `geosite:cn` 直连。
- 广告规则可选择阻止。
- 其他流量通过代理。

#### 黑名单

- GFW List、Telegram 等黑名单流量通过代理。
- 其他流量直连。

#### 全局

- 局域网直连。
- 其他流量全部代理。

#### 自定义

用户可按以下条件添加规则：

- 完整域名
- 域名后缀
- IP/CIDR
- GeoSite
- GeoIP
- 进程名称
- 目标端口
- 网络类型 TCP/UDP

规则动作：

- 代理
- 直连
- 阻止
- 指定节点或指定 SOCKS5

规则按从上到下匹配，必须存在最终兜底规则。

### 5.2 规则库

- GeoSite
- GeoIP
- GFW List
- 可配置远程规则提供方
- 支持手动和定时更新
- 更新前校验文件完整性
- 保留上一个可用版本用于回滚

### 5.3 增强模式

- Windows 系统代理。
- TUN 模式。
- DNS 分流与防泄漏。
- 管理员权限检查。
- 系统异常退出后恢复原系统代理设置。

## 6. 应用代理

提供类似 Proxifier 的应用级代理规则：

- 选择 `.exe` 程序。
- 记录完整程序路径，而不是只记录文件名。
- 绑定一个本地 SOCKS5。
- 启用、停用和删除规则。
- 显示程序当前是否运行。
- SOCKS5 失效时阻止启动或要求重新选择。

实现方式按优先级选择：

1. 应用自身支持的代理参数或环境变量。
2. 启动包装器注入代理环境变量。
3. Windows Filtering Platform 或可靠的进程级网络转发组件。

不要通过不受信任的 DLL 注入实现。

## 7. Claude Code 多账号项目启动器

### 7.1 账号隔离

每个账号拥有独立配置目录：

```text
C:\Users\用户名\ClaudeProfiles\account1
C:\Users\用户名\ClaudeProfiles\account2
```

通过以下变量隔离：

```powershell
$env:CLAUDE_CONFIG_DIR="账号配置目录"
```

每个目录独立保存 Claude 登录资料、设置、历史、插件、Skills、MCP 和用户级指令。

界面不得读取或显示 Token、API Key 和凭据文件内容。

### 7.2 项目启动台

项目字段：

- 名称
- 目录
- 描述
- 图标
- 项目类型
- Git 状态与分支
- 默认账号
- 默认浏览器
- 默认终端
- 默认命令模板
- 最近启动时间
- 运行状态

一键启动流程：

1. 检查环境是否检测通过。
2. 检查全局固定出口 IP。
3. 检查项目目录。
4. 检查 Claude Code 程序。
5. 检查账号配置目录。
6. 检查账号登录状态。
7. 设置 `CLAUDE_CONFIG_DIR`。
8. 打开绑定浏览器。
9. 打开终端并进入项目目录。
10. 启动 Claude Code。
11. 执行预设命令和初始提示词。

所有步骤必须返回实时进度和具体错误。

### 7.3 账号管理

显示：

- 账号名称
- 邮箱
- 配置目录
- 登录状态
- 绑定浏览器
- 运行项目数量
- 最后使用和验证时间

操作：

- 新增账号
- 登录或重新登录
- 执行 `claude auth status --text`
- 打开配置目录
- 打开绑定浏览器
- 复制启动命令
- 删除账号

删除账号前必须二次确认，并说明会删除本机登录状态、设置和会话。

### 7.4 浏览器身份

支持：

- 比特浏览器
- Google Chrome
- Microsoft Edge
- 自定义浏览器

比特浏览器优先使用官方本地 API 打开指定窗口。

如果不能把 OAuth 地址传入指定窗口：

1. 复制登录地址。
2. 打开指定浏览器窗口。
3. 提示用户粘贴链接。

禁止默认把授权链接交给系统浏览器，以免登录到错误账号。

### 7.5 命令模板

内置：

```text
claude
claude --continue
claude --model sonnet
claude "读取项目说明，检查当前进度，然后继续开发。"
```

自定义模板字段：

- 名称
- 启动前命令
- Claude 启动参数
- 初始提示词
- 启动后命令
- 默认账号
- 默认项目
- 默认终端

### 7.6 并发与 Worktree

同一项目已经运行时，提供：

- 返回
- 只读打开
- 仍然启动
- 创建 Git Worktree 后启动

建议目录：

```text
D:\worktrees\项目名-account1
```

每个 Worktree 使用独立分支。创建失败时不得继续启动。

## 8. Claude Code 全局固定 IP

所有 Claude Code 账号和项目共用一个固定出口 IP，不跟随普通系统代理节点切换。

启动前必须检测：

- Claude Code EXE 实际出口 IP。
- 注入的代理环境出口 IP。
- 当前全局绑定 IP。

三者必须一致。

如果不一致：

1. 阻止启动。
2. 显示三个 IP 的对比。
3. 要求先解绑旧 IP。
4. 重新检测环境。
5. 绑定新的稳定 IP。
6. 再允许启动。

解绑 IP 不得删除账号、项目、会话或登录资料。

固定 IP 对应节点被引用时不得删除，必须先解除绑定。

## 9. 授权与卡密

授权数据：

- 卡密 ID
- 授权版本
- 到期时间
- 设备数量限制
- 当前设备指纹
- 签发时间
- 最近验证时间
- 撤销状态

安全要求：

- 卡密只提交给服务端验证。
- 服务端返回带签名的短期授权凭证。
- 客户端内置公钥，只验证签名，不保存签名私钥。
- 到期时间以服务端为准。
- 使用 Windows DPAPI 保存刷新凭证。
- 定期在线校验并允许合理离线宽限期。
- 设备指纹应允许硬件小幅变化，不能只绑定单一 MAC 地址。
- Renderer 不得直接决定授权是否有效。

前端输入任意字符串不能激活正式授权。

---

## 10. 安全与隐私

- Electron 启用 `contextIsolation`。
- Renderer 禁用 `nodeIntegration`。
- 使用严格 CSP。
- IPC 使用白名单和参数校验。
- 进程执行禁止拼接未转义的 shell 字符串。
- 路径必须标准化并验证。
- 敏感日志必须脱敏。
- 二维码解析在本机完成。
- 默认仅监听 `127.0.0.1`。
- 自动恢复被修改的系统代理设置。
- 高风险操作记录审计事件，但不记录凭据。

---

## 11. 验收标准

### 节点与 SOCKS5

- 能批量导入有效节点并报告无效项。
- 能通过代理核心完成真实出口测试。
- 删除节点会正确处理关联端口和应用规则。
- SOCKS5 端口冲突能自动处理。

### 路由

- 四种模式生成正确的最终配置。
- 自定义规则顺序可调整。
- TUN 和 DNS 不产生明显泄漏。
- 核心异常退出后系统代理可恢复。

### Claude Code

- 两个账号可同时运行，配置和会话不互相覆盖。
- 项目能使用默认账号一键启动。
- 错误浏览器身份不会被自动用于 OAuth。
- 同项目并发会触发冲突提示。
- Worktree 创建后使用独立目录和分支。
- 固定 IP 不一致时无法启动。

### 授权

- 修改本地时间不能延长授权。
- 修改本地数据库不能伪造有效授权。
- 撤销卡密后客户端在下次在线校验时失效。
- UI 不显示完整卡密和任何凭据内容。
